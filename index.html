Incident intake

What is established—and what is only the story around it?

Answer

A 64-bit Windows DLL with backdoor capabilities is code-backed. The invoice lure and employee HTTPS traffic are scenario facts. Successful compromise, live C2, and attribution are not established.

The code is evidence.
The scenario is context.

A strong case study keeps those categories separate. Sagerunex exposes real control paths for impersonation, encrypted configuration, network discovery, proxy fallback, command execution, and file transfer. It does not expose the actual infrastructure or prove any action succeeded.

Observed evidence includes the PE machine value, export, API calls, exact strings, offsets, and branch constants reported in the supplied analysis.

01

Entry and identity

What happens before the first beacon attempt?

Answer

MainEntry prepares TS_FB56.tmp, checks 0xC91F3B, may borrow the explorer.exe token, decodes 1,888 bytes, and enters the beacon loop.

STEP 01 / EXPORTED ENTRY

MainEntry establishes the case’s execution spine.

The export belongs to MainDLL.dll. An export-directory reference is not itself a direct internal call.

02

Configuration and storage

Why do two different transforms appear in the same sample?

Answer

A chained XOR transform handles a 1,888-byte in-memory region. Separate RC4-like logic protects a 1,600-byte configuration stored beneath AppData.

TRANSFORM AMemory region
0x7601,888 bytes

Bytes are processed from end to beginning using the preceding stored byte. The first byte is XORed with 0xAD.

TRANSFORM BPersisted config
0x6401,600 bytes
PRGA

A wrapper prepares state, then a swap/XOR keystream operation transforms the configuration in place.

%APPDATA%\Microsoft\Protect\Windows\DMI%X.DAT

This proves disk-backed configuration handling and timestomping. It does not prove boot or logon autostart persistence.

CONFIGURATION LIFECYCLE

Initialize session → construct AppData path → load existing 0x640-byte file or use supplied/default configuration → apply RC4-like transform → validate timing fields → save and timestomp when required → use for C2 activity.

VERDICT / EVIDENCE-BOUNDED

A patient backdoor built for constrained networks.

Sagerunex combines conditional token impersonation, reverse chained XOR decoding, RC4-like protected local configuration, deliberate timestomping, five-slot endpoint rotation, local-hour scheduling, layered proxy discovery, remote execution, and chunk-based file movement.

The strongest architectural finding is its communication subsystem: it extracts host networking settings and attempts several routes rather than assuming direct Internet access.

That architecture is strongly supported. The real endpoints, successful runtime effects, autostart mechanism, propagation, and attribution are not.
